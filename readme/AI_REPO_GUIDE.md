# AI Repo Guide

This guide helps agents build a mental model of the repo before editing. The short version: this is both a design system documentation site and a package that publishes reusable components.

## Main Outputs

| Output | Source | Build path |
| --- | --- | --- |
| Docs site | `docs/**`, `src/**`, `assets/**`, `public/**` | `vite build` through `npm run build:docs` |
| Vue component package | `src/**` | Vite library mode through `npm run build` |
| Static/web component assets | `assets/ts/**`, `assets/sass/**`, `assets/svg/**`, `assets/img/**`, `assets/fonts/**` | `npm run compile` and `npm run copy` |
| Laravel Blade package stub | `blade/**` | Not part of the main Vite flow |

## Directory Map

| Path | Purpose |
| --- | --- |
| `assets/ts/components` | Custom element classes, usually one folder per `iam-*` component. |
| `assets/ts/modules` | Shared TypeScript modules, helpers, and custom unit tests. |
| `assets/ts/scripts.ts` | Main browser entry that initialises global modules on `DOMContentLoaded`. |
| `assets/sass` | Source Sass for core styles, elements, utilities, and components. |
| `assets/css` | Compiled CSS output from Sass. Do not hand-edit for normal changes. |
| `assets/js` | Compiled TypeScript and Rollup output. Do not hand-edit for normal changes. |
| `components.json` | Component names that Rollup uses to build individual web component bundles. |
| `src/components` | Vue components exported by the package. |
| `src/foundations` | Foundation-level Vue exports such as logos. |
| `src/index.js` | Public Vue package export barrel. |
| `docs` | Vue documentation app, routes, examples, and design system pages. |
| `public` | Static files served by Vite and copied packaged assets. |
| `local_modules` | Local build, test, copy, audit, and generation scripts. |
| `dist` | Library build output. Generated by Vite library mode. |
| `tests/setup` | Test setup files used by older or package-level test tooling. |
| `blade` | Small Laravel package/stub area with a service provider and Blade views. |

## Build Flow

The static asset build is intentionally layered:

1. `npm run compile:sass` compiles `assets/sass/**` into `assets/css/**`.
2. `npm run compile:ts` transpiles `assets/ts/**` into `assets/js/**` using `tscompileconfig.json`.
3. `npm run compile:js` runs Rollup over `assets/js/scripts.js` and the component entries in `components.json`.
4. Rollup injects compiled component CSS into minified web component bundles where the config uses placeholder replacement.
5. `npm run copy` copies selected CSS, JS, images, SVG, fonts, favicons, and utility files into `public/**`.
6. Vite builds either the docs site or the library package depending on script and mode.

## Important Entry Points

- `package.json` defines all scripts and package metadata.
- `vite.config.ts` configures docs and library builds, Vue, aliases, and `iam-*` custom element handling.
- `rollup.config.cjs` builds the global scripts bundle and every component in `components.json`.
- `rollup-component.config.cjs` builds a single component, usually from the local watcher.
- `local_modules/components.cjs` watches component/module/Sass changes and invokes single-component Rollup builds.
- `local_modules/test.cjs` discovers and runs `assets/ts/**/*.test.ts` files.

## Which Area To Edit

| Request type | Start here | Also check |
| --- | --- | --- |
| Change an `iam-*` web component | `assets/ts/components/<name>` | `assets/ts/modules`, `assets/sass/components`, `docs/views` |
| Change shared component logic | `assets/ts/modules/<name>.ts` | Matching `*.test.ts` and web component class |
| Change visual styling | `assets/sass/**` | Generated CSS after `npm run compile:sass` or `npm run compile` |
| Change Vue package API | `src/components/**` or `src/foundations/**` | `src/index.js`, docs pages, package build |
| Change docs content/routes | `docs/views/**`, `docs/routes.ts` | `public` data/images used by the page |
| Change package/build behavior | `package.json`, `vite.config.ts`, `rollup*.cjs`, `local_modules/**` | Validation scripts and generated output |

## Generated Output Guidance

Generated files can be committed in this repo, but avoid editing them directly:

- `assets/css/**`
- `assets/js/**`
- `public/assets/**`
- `public/utilities/**`
- `dist/**`

If a source change should alter generated output, run the appropriate compile/build script and review the generated diff.

## Known Repo Characteristics

- The TypeScript compile config currently has `noCheck: true`, so lint and tests carry more of the safety burden for `assets/ts`.
- The unit test setup is custom and lightweight, not Jest. Assertions come from `assets/ts/modules/test.ts`.
- Some docs examples use static JSON in `public/**`.
- `docs/routes.ts` is large and is the main navigation/search registration point for documentation pages.
- `assets/ts/components.ts` contains an older/lazy custom element loader path. The main startup file is `assets/ts/scripts.ts`.
