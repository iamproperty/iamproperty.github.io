Data-backed controls below exercise selection across pages, filtering, sorting and retrieving original objects. 


        

      
      
Using your endpoint

      

        Add data-backed before mounting the element, then pass your endpoint's records to setData. Use a stable unique
        ID, not the row position. The backend payload remains the consuming application's responsibility.
      

      
<iam-table id="records" data-backed data-selectall data-show="50"></iam-table>

await customElements.whenDefined('iam-table');
const table = document.querySelector('#records');
// Extract the records from whichever response shape your backend uses.
table.setData(records, {
  rowKey: 'id', // or record => record.nested.identifier
  columns: [
    { key: 'property', label: 'Property', sort: true, filters: [{ type: 'text' }] },
    { key: 'currentPrice', label: 'Current Price', sort: true, format: 'price', filters: [{ type: 'price' }] },
    { key: 'weeksOnMarket', label: 'Weeks on Market', sort: true, filters: [{ type: 'number', operator: 'equals', value: '11' }] }
  ]
});
const selected = table.getSelectedRecords(); // Original objects, including off-page records
const ids = table.getSelectedIds();
table.setFilter(record => record.matchCriteria === 'full');
table.setSort((a, b) => a.property.localeCompare(b.property));
table.setFilter(null); // Clear the application predicate; header filters and selection persist


      

        Vue: use <Table data-backed data-selectall :items="records" :fields="fields" row-key="id" />. Replace the
        items array when records change. Access getSelectedRecords() through the Vue component ref. Choose data-backed
        mode at mount time.
      

      

        Columns render plain text by default. This example uses render callbacks for whole-pound prices, ISO dates,
        one-decimal reduction percentages and the View property button. Sorting and filtering still use the underlying
        typed values. All 13 data columns have header controls; the action column does not. Expandable mobile rows and
        the original application's drill-through behaviour are not part of this demo.
      

      
Configuring columns with existing header attributes

      

        You can instead supply a header before mounting the table and omit the columns option. Add data-key to map the
        heading to a record property (or supply corresponding JavaScript column keys in the same order).
      

      
<iam-table id="properties" data-backed data-selectall>
  <table>
    <thead><tr>
      <th data-key="property" data-filters='[{"type":"text"}]' data-sort>Property</th>
      <th data-key="listedDate" data-filters='[{"type":"date"}]' data-sort data-format="date">Date listed</th>
      <th data-key="currentPrice" data-filters='[{"type":"price"}]' data-sort data-format="price">Current list price</th>
      <th data-key="branch" data-filters data-sort>Branch</th>
      <th data-key="weeksOnMarket" data-filters='[{"type":"number","operator":"equals","value":"11"}]' data-sort>Weeks on market</th>
    </tr></thead>
  </table>
</iam-table>

await customElements.whenDefined('iam-table');
document.querySelector('#properties').setData(records, { rowKey: 'id' });

      

        Blank data-filters enables a text filter. Use type: "select" for options from the full dataset. Text matching is
        case-insensitive; numeric and price ranges are inclusive. Date filters accept ISO dates or UK DD/MM/YYYY and
        DD.MM.YYYY values. Clearing a column's filter uses its Reset button. Existing filter state is retained when data
        or column definitions are refreshed.
      

      

        Select all covers the current matching records across pages and retains prior selections outside the filter.
        Clear selection clears everything. Refreshing data preserves surviving selected IDs; new records are not
        automatically selected. IDs must be unique strings or finite numbers.
